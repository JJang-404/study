# 02. IPv4 서브넷과 기본 게이트웨이

## 이번 학습 목표

- CIDR 프리픽스(`/24`, `/26`)와 서브넷 마스크의 관계를 설명합니다.
- IPv4 주소에서 네트워크 주소, 브로드캐스트 주소, 일반 호스트 주소 범위를 찾습니다.
- 목적지 IP가 같은 네트워크인지 판단하고, 다른 네트워크라면 기본 게이트웨이를 거치는 이유를 설명합니다.

## 1. 서브넷은 무엇인가요?

IPv4 주소는 32비트입니다. 서브넷 마스크는 그중 어디까지가 네트워크를 나타내는 비트인지 표시합니다. CIDR 표기에서 `/24`는 앞의 24비트가 네트워크 부분이고 나머지 8비트가 호스트 부분이라는 뜻입니다.

예를 들어 `192.168.10.25/24`의 마스크는 `255.255.255.0`입니다. 앞의 세 옥텟(`192.168.10`)이 네트워크를 구분하고, 마지막 옥텟이 해당 네트워크 안의 주소를 구분합니다.

| CIDR | 서브넷 마스크 | 전체 주소 수 | 보통의 사용 가능 호스트 수 |
|---|---|---:|---:|
| `/24` | `255.255.255.0` | 256 | 254 |
| `/25` | `255.255.255.128` | 128 | 126 |
| `/26` | `255.255.255.192` | 64 | 62 |
| `/27` | `255.255.255.224` | 32 | 30 |
| `/28` | `255.255.255.240` | 16 | 14 |

일반적인 `/0`부터 `/30`까지는 전체 주소 수가 `2^(32-프리픽스 길이)`입니다. 전통적인 서브넷에서는 네트워크 주소와 브로드캐스트 주소를 빼서 호스트 수를 계산합니다. `/31`은 점대점 링크에서 두 주소 모두 호스트로 쓸 수 있는 예외가 있고, `/32`는 단일 주소를 나타내므로 위 표의 단순 계산을 그대로 적용하지 않습니다.

## 2. `/26` 주소 범위 계산 예시

다음 주소가 있다고 가정합니다.

- 장치 주소: `192.168.10.77/26`
- 마스크: `255.255.255.192`

`/26`은 네트워크 비트 26개와 호스트 비트 6개를 뜻합니다. 호스트 비트가 6개이므로 한 블록의 주소 수는 `2^6 = 64`개입니다. 마지막 옥텟의 블록 크기가 64이므로 네트워크가 `0`, `64`, `128`, `192`에서 시작합니다.

`77`은 `64` 이상 `128` 미만이므로 이 주소가 속한 범위는 다음과 같습니다.

- 네트워크 주소: `192.168.10.64`
- 일반 호스트 주소: `192.168.10.65`~`192.168.10.126`
- 브로드캐스트 주소: `192.168.10.127`
- 전체 주소 수: 64개, 일반 호스트 주소 수: 62개

예를 들어 `192.168.10.110/26`은 같은 네트워크입니다. `192.168.10.130/26`은 `192.168.10.128/26` 네트워크에 있으므로 다른 네트워크입니다.

## 3. 같은 네트워크인지 판단하기

장치는 자신의 IP 주소와 서브넷 마스크를 사용해 목적지가 로컬 네트워크에 있는지 판단합니다. 두 주소에 같은 마스크를 적용해 네트워크 부분이 같으면 같은 서브넷이고, 다르면 다른 서브넷입니다.

- 내 주소: `192.168.10.77/26` → 네트워크 `192.168.10.64/26`
- 목적지 A: `192.168.10.110/26` → 네트워크 `192.168.10.64/26` → 같은 서브넷
- 목적지 B: `192.168.10.130/26` → 네트워크 `192.168.10.128/26` → 다른 서브넷

같은 서브넷의 목적지라면 장치는 로컬 링크에서 목적지 장치의 이더넷 주소를 알아내 전달합니다. 다른 서브넷의 목적지라면 패킷을 기본 게이트웨이(다음 홉)로 보냅니다. 게이트웨이는 보통 라우터의 로컬 네트워크 쪽 인터페이스 주소입니다.

기본 게이트웨이는 내 컴퓨터와 같은 서브넷에 있어야 합니다. 앞의 예에서 `192.168.10.65/26`은 같은 서브넷의 가능한 게이트웨이 예시지만, 실제 네트워크에서는 관리자가 정한 주소를 사용합니다.

## 4. 서브넷 마스크를 읽는 법

마스크의 네트워크 비트는 왼쪽부터 1이 이어지고, 호스트 비트는 그 뒤에 0이 이어집니다.

- `255.255.255.0` = `/24`
- `255.255.255.128` = `/25` (마지막 옥텟 `10000000`)
- `255.255.255.192` = `/26` (마지막 옥텟 `11000000`)
- `255.255.255.224` = `/27` (마지막 옥텟 `11100000`)

`/26`에서 마지막 옥텟의 블록 크기는 `256 - 192 = 64`입니다. 따라서 마지막 옥텟이 0, 64, 128, 192로 시작하는 네트워크로 나뉩니다.

## 5. 진단할 때 확인할 점

Windows에서 현재 설정을 확인합니다.

```powershell
ipconfig /all
```

다음 항목을 살펴봅니다.

- IP 주소와 서브넷 마스크가 서로 맞는가?
- 기본 게이트웨이가 현재 IP와 같은 서브넷에 있는가?
- IP 주소가 `169.254.x.x`인가? 그렇다면 DHCP에서 설정을 받지 못해 자동 구성 주소가 사용 중일 가능성이 있습니다. 이것만으로 원인을 단정하지는 않습니다.
- 같은 서브넷 장치와 통신되는가? 게이트웨이 응답이 없는 경우에도 ICMP 차단 가능성을 고려합니다.
- 게이트웨이에는 도달하지만 외부 IP에 도달하지 못하는가? 라우팅, 방화벽, 상위 연결 등 다음 구간을 따로 확인합니다.

IP 주소나 게이트웨이를 임의로 바꾸면 주소 충돌이나 연결 중단이 생길 수 있습니다. 개인 실습 환경에서만 설정을 바꾸고, 변경 전 현재 값을 기록해 둡니다.

## 6. 연습 문제

먼저 직접 계산한 뒤 아래 답을 확인합니다.

### 문제 A

`192.168.1.140/25`의 네트워크 주소, 브로드캐스트 주소, 일반 호스트 범위를 구합니다.

<details>
<summary>답 확인</summary>

- `/25`의 블록 크기는 128입니다.
- `140`은 128~255 블록에 속합니다.
- 네트워크 주소: `192.168.1.128`
- 일반 호스트 주소: `192.168.1.129`~`192.168.1.254`
- 브로드캐스트 주소: `192.168.1.255`

</details>

### 문제 B

내 주소가 `10.0.4.18/23`일 때 `10.0.5.200`은 같은 서브넷인가요?

<details>
<summary>답 확인</summary>

`/23`은 세 번째 옥텟의 블록 크기가 2입니다. `10.0.4.0`부터 `10.0.5.255`까지가 `10.0.4.0/23`이므로 `10.0.5.200`은 같은 서브넷입니다.

</details>
