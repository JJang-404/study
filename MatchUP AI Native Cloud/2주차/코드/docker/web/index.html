확인 경로

URL의미
/healthzweb 자체 상태. nginx가 직접 응답 (업스트림 미확인)
/healthz/chainweb → api → db 전 구간. api의 상세 점검 결과를 그대로 전달
/api/healthzapi 상태 + db 점검 (프록시 경유)
/api/livezapi 프로세스 생존만 확인 (db 미확인, liveness probe용)

이 화면은 위 경로를 브라우저에서 호출해 채워집니다. 새로고침하면 다른 파드(replica)가 응답해 파드 이름이 바뀔 수 있습니다.

용어 설명 (처음 배우는 분께)

용어뜻
파드(Pod)쿠버네티스에서 컨테이너를 실행하는 가장 작은 단위. 이 화면에 나오는 "파드 이름"이 지금 응답한 파드다.
replicas(복제본)같은 파드를 몇 개 띄울지. web·api는 2개라서 하나가 죽어도 서비스가 계속되고, 새로고침하면 다른 파드가 응답할 수 있다. db는 데이터 보존이 중요해 1개.
namespace클러스터 안의 구획. 여기서는 web / api / db 세 계층을 각각 나눠 담았다.
Service파드 앞에 놓이는 고정 주소. 파드는 죽으면 이름·IP가 바뀌지만 Service 주소는 그대로라서 다른 계층이 이 주소로 찾아온다.
NodePort / ClusterIPService의 종류. NodePort는 클러스터 밖(내 PC)에서도 접속 가능(web만). ClusterIP는 클러스터 안에서만 접속 가능(api·db).
*.svc.cluster.local클러스터 내부 주소 형식 <Service>.<namespace>.svc.cluster.local. 예: db.db.svc.cluster.local = db namespace의 db Service.
healthz / livez"살아 있나요?"를 묻는 확인용 주소. livez는 프로세스 생존만, healthz는 db 연결까지 점검한다.
