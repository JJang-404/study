# 4-3 RAG 작업·검증 메모

## 2026-11-09 · 현재 결정

- 지식베이스: Galaxy Watch7 한국어 문서 4개, 36청크. 청크 최대 300자, 오버랩 40자.
- 검색 기본값: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`.
- 생성 모델: 4-1의 `llm.chat()`을 통해 로컬 Ollama `llama3.2`, temperature 0.0. 이 실습에서는 생성 LLM을 변경하지 않았다.
- 임계치: 0.25. 시작값으로 사용하며, 점수만으로 문서 근거의 충분성을 판단하지 않는다.

## 왜 임베딩 모델을 바꿨나

한국어 문서와 질문에 두 임베딩 후보를 같은 12개 질의로 비교했다. 다국어 모델은 답이 있는 8개 질문에서 기대 문서를 8/8 top-3에 포함했고, 답이 없는 네 질문을 모두 생성 전에 차단했다(12/12 점검). `all-MiniLM-L6-v2`는 각각 5/8, 4/4(9/12 점검)였다. 따라서 현재 한국어 자료의 기본값은 다국어 모델로 둔다. 표본이 작아 일반적인 우열로 확대 해석하지 않는다. 점수 분포가 다를 수 있으므로 모델 간 원점수 크기도 직접 비교하지 않는다.

모델 변경은 검색 벡터와 코사인 점수의 변경이다. `llama3.2`는 4-1 헬퍼 재사용 조건을 따라 유지했다. 생성 LLM을 바꾸면 답변을 새로 평가해야 하지만 임베딩 검색 점수는 바뀌지 않는다. 임베딩 모델 교체 때는 반드시 인덱스를 재구축한다.

## 근거 누락·문서 밖 정보 검사

기존 지식베이스에는 제품과 환불 관련 출처 불명 정보가 포함돼 있었다. 이전 로그의 검색 문맥에도 문제의 정보가 들어 있어 그 답을 문맥 없는 모델 누출이라고 단정할 수는 없다. 재현 가능한 문제는 근거 문서 자체의 출처 신뢰성이 부족했다는 것이다. 현재는 한국어 제품 FAQ, 사용 안내, 환불 정책, 보증 안내로 지식베이스를 교체하고 출처와 적용 범위를 기록한다.

현재 12개 질의 평가에서 문서 밖 질문의 최고점은 `.032`부터 `.670`까지였다. 업데이트 날짜·정확한 금액처럼 문서에 없는 값을 묻는 질문도 0.25를 넘을 수 있었다. 그래서 `rag.py`는 LLM 호출 전에 날짜, 요청 숫자·단위, 금액 근거와 질문 핵심 표현을 함께 검사한다. 최종 다국어 모델 평가에서는 답변 불가 질의 4/4가 거절됐다.

게이트를 일부러 우회한 업데이트 날짜 질문에서는 LLM이 구체적인 날짜를 만들지는 않았지만, 문서에서 확인되지 않는 일반 안내를 덧붙였다. 정확한 금액 질문은 임의 숫자를 만들지 않았다. 따라서 지식 누출은 특정 단어나 단일 답변으로만 판정하지 않고, 여러 유형의 문서 밖 질의에서 주장과 인용이 실제 근거에 있는지 확인한다.

## 반복 검증 원칙

- 검증은 LLM 호출 전 점수·top-k 출처·threshold 판정을 출력하는 단계와, 생성 뒤 답변·인용을 확인하는 단계로 나눈다.
- 답이 있는 질의는 기대 문서가 검색 결과에 포함되는지, 핵심 답이 인용 청크에 실제 들어 있는지 확인한다.
- 답이 없는 질의는 threshold 통과 여부만 보지 않고 질문에 요구된 날짜·수량·금액 단서가 있는지 검사한다. 근거가 없으면 생성 호출을 차단한다.
- 실패가 있으면 원인을 고치고 같은 평가 묶음을 다시 실행한다. 모든 테스트가 통과할 때까지 반복하되, 통과한 범위와 표본 크기를 함께 기록한다.
- 임계치 0.25는 실습 기본 시작값이다. 문서·모델·질문 분포가 바뀌면 재평가한다. 문자열 기반 게이트는 최소 구현이라 미탐·오탐 가능성이 남는다.
- 인용은 출처 파일명만 붙이면 충분하지 않다. 답의 핵심 문장이 해당 청크에 존재하는지 확인한다.
