임베딩 모델은 질문과 청크를 벡터로 바꾸어 검색 순위와 유사도 점수를 결정합니다. 생성 모델은 검색 결과를 받아 답변 문장을 만듭니다. 이번에는 한국어 검색 비교 결과에 따라 임베딩을 다국어 모델로 정했고, 4-1 `llm.chat()` 재사용 조건에 따라 생성 모델은 `llama3.2` 그대로 두었습니다. 따라서 아래 모델 비교표는 검색과 생성 전 차단 평가이며 생성 문장 품질 비교가 아닙니다.

| 파일 | 포함 내용 |

| `Product FAQ.md` | 배터리, 방수와 수영 후 관리, 호환 기기, 배송·구성, 건강 기능 |

| `warranty.md` | 보증 기간, 무상·유상 수리 기준, 접수 흐름 |

`build_index.py`가 제목 경계를 유지해 최대 300자, 오버랩 40자로 청킹하고 `index.npz`에 임베딩·문서명·청크 ID를 저장합니다. 현재 인덱스 메타데이터를 다시 확인한 결과 모델은 `paraphrase-multilingual-MiniLM-L12-v2`, 벡터는 `(36, 384)`, 문서는 위 네 파일입니다. 질문도 인덱스와 같은 임베딩 모델로 벡터화합니다.

## 3. 평가 질문과 판정 기준

모델 비교용 질문 12개를 사용했습니다. 답이 있는 8개는 사전에 정한 기대 문서가 검색 top-3 안에 있는지 평가했습니다. 답이 없는 4개는 파리 인구(주제 무관), 업데이트 날짜(문서에 날짜 없음), 정확한 반품 배송비(문서에 금액 없음), 토성 위성(주제 무관)입니다. 이 네 질문은 최고 점수가 threshold를 넘더라도 근거 게이트가 LLM 호출을 막는지 평가합니다.

시연용 질문은 답변 가능한 연결·수영 후 관리·반품 조건과, 무관 질문 및 날짜·기간·비용 근거가 없는 질문으로 구성했습니다. 판정은 두 단계로 구분합니다.

1. 최고 점수가 0.25 미만이면 threshold에서 생성 차단.
2. threshold 이상이어도 질문의 핵심 표현 및 요구된 날짜·숫자·단위·금액이 근거 청크에 없으면 근거 게이트에서 생성 차단.

## 4. 임베딩 모델 비교

동일한 한국어 질문 12개와 동일 문서 36청크에서 측정했습니다. IN 범위는 답이 있는 8개 질문의 최고 유사도 최솟값~최댓값이고, OUT 범위는 답이 없는 4개의 최고 유사도 범위입니다.

| 임베딩 모델 | IN 범위 (8개) | OUT 범위 (4개) | threshold만으로 분리 가능? | 기대 문서 Hit@3 | 근거 게이트 OUT 차단 |
|---|---:|---:|---|---:|---:|
| `all-MiniLM-L6-v2` | 0.699–0.844 | 0.657–0.789 | 불가, 범위 겹침 | 5/8 | 4/4 |
| `paraphrase-multilingual-MiniLM-L12-v2` | 0.648–0.787 | 0.032–0.670 | 불가, 0.648–0.670 겹침 | 8/8 | 4/4 |

분리 기준은 모든 OUT 최고 점수보다 높고 모든 IN 최고 점수보다 낮은 threshold가 존재하는지입니다. 두 모델 모두 IN·OUT 범위가 겹쳐 단일 threshold로 완전 분리할 수 없습니다. 예를 들어 다국어 모델은 문서 안 답변 질문의 최저점이 0.648인데, 답이 없는 배송비 질문은 0.670입니다. threshold를 0.670보다 높이면 해당 OUT은 막지만 IN 질문도 일부 막습니다. 반대로 그보다 낮추면 이 OUT 질문을 생성 단계에서 막지 못합니다.

그래서 threshold만으로 완결된 판정을 하지 않습니다. 다국어 모델은 이 한국어 평가 집합에서 기대 문서를 top-3에 더 자주 포함했고(8/8 대 5/8), 추가 근거 게이트와 함께 OUT 4개를 모두 생성 전에 차단했습니다. 12개 질문에 한정한 결과이므로 일반적인 모델 우열이나 실제 서비스 정확도로 해석하지 않습니다. 모델 카드 역시 각각 영어 중심과 다국어 모델 특성을 설명합니다: [all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2), [paraphrase-multilingual-MiniLM-L12-v2](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2).

## 5. 시연 결과

| 1 | 워치7 44mm를 처음 켰을 때 휴대전화와 어떻게 연결하나요? | 0.714 | `Product FAQ.md#1` | `usage_guide.md` (top-3 2위) | 생성 허용: 핵심 설정 근거가 top-3에 있음 |
| 2 | 수영 후 워치를 어떻게 헹구고 말려야 하나요? | 0.622 | `Product FAQ.md#5` | `Product FAQ.md` (관리 청크 top-3 포함) | 생성 허용: 관리 근거 확인 |
| 3 | 온라인 구매 상품은 수령 후 며칠 이내 청약철회할 수 있나요? | 0.616 | `Refund Policy.md#2` | `Refund Policy.md#2` | 생성 허용: 기간 근거와 출처 문장 확인 |
| 4 | 프랑스 파리의 현재 인구는 얼마인가요? | 0.047 | `warranty.md#6` | 없음 | threshold 미달 및 핵심어 근거 없음으로 차단 |

| 7 | 워치7 왕복 반품 배송비는 정확히 얼마인가요? | 0.670 | `Refund Policy.md#5` | 없음 (정확한 고정 금액 없음) | threshold 통과, 금액 근거 없어 차단 |

## 6. 임계치가 IN/OUT을 나누지 못하는 이유

임베딩 유사도는 질문과 청크의 의미적 가까움을 나타내는 검색 신호입니다. 문서가 질문과 같은 주제를 다루면 필요한 세부 값이 없어도 점수가 높게 나올 수 있습니다. 업데이트 날짜 질문은 업데이트 안내 청크와 가까웠고, 정확한 배송비 질문은 반품·비용 안내 청크와 가까웠습니다. 이 때문에 OUT의 최고 점수가 IN의 일부 점수보다 높았습니다.

`0.25`는 검색 결과를 너무 낮은 유사도에서 무조건 생성하지 않게 하는 시작 기준입니다. 위 측정에서는 OUT 네 질문 중 파리만 threshold 아래였고 나머지 세 질문은 통과했습니다. 따라서 0.25는 “문서에 답이 있다”는 보증 기준으로 작동하지 않습니다. 실습 기본값은 유지하되, 날짜·수량·비용 요구가 실제 청크에 있는지 확인하는 근거 게이트와 함께 씁니다. 서로 다른 임베딩 모델의 점수 범위도 달라질 수 있어 모델을 바꾸면 인덱스를 재구축하고 점수 분포를 다시 측정해야 합니다.

## 7. 근거 없는 답변 차단 및 누출 점검

### 차단 검증

| 답변 불가 유형 | 최고 유사도 | 0.25 threshold | 추가 검사 | 최종 동작 |
|---|---:|---|---|---|
| 주제 무관: 파리 인구 | 0.047 | 미달 | 핵심어도 근거와 불일치 | LLM 호출 안 함 |
| 날짜 없음: 다음 업데이트 날짜 | 0.534 | 통과 | 날짜 형식의 근거 문장 없음 | LLM 호출 안 함 |
| 세부 기간 없음: 단순 변심 기간 | 0.579 | 통과 | 요청 단위 숫자 없음 | LLM 호출 안 함 |
| 세부 금액 없음: 정확한 왕복 배송비 | 0.670 | 통과 | `숫자 + 원` 근거 없음 | LLM 호출 안 함 |

따라서 차단 검증은 수행했습니다. 4개 질문 모두 `answer()`의 생성 전 경로에서 거절되며, threshold 단독으로 차단된 것은 1개, 근거 적합성 검사가 추가로 차단한 것은 3개입니다. 이 분해를 통해 임계치와 근거 검사가 서로 다른 역할을 하는 것을 확인했습니다.

### 게이트 우회 진단

문서에 없는 정보를 모델이 보완하는지 보기 위해 진단 모드에서 날짜·기간·정확한 금액 질문을 의도적으로 근거 게이트 없이 생성 모델에 전달했습니다. 업데이트 날짜 질문에서는 구체적인 날짜를 만들지는 않았지만, 검색 문맥에 명시되지 않은 일반 업데이트 안내를 덧붙였습니다. 정확한 비용 질문에서는 임의 금액을 만들지 않고 주문·조건 확인이 필요하다고 답했습니다. 이 결과는 같은 모델도 질문별로 보완 방식이 달라질 수 있음을 보여줍니다. 날짜 누락 진단만으로 모든 유형의 누출 여부를 일반화하지 않으며, 운영 경로에서는 게이트가 통과하지 않으면 생성하지 않습니다.

이전 실습 데이터에 출처가 확인되지 않은 정책 내용이 있었고, 과거 실행의 검색 문맥에도 그 내용이 포함돼 있었습니다. 따라서 과거 응답을 “검색 문맥에 전혀 없던 내용이 모델에서 나왔다”고 단정하지 않습니다. 확인 가능한 문제는 출처가 검증되지 않은 문서가 지식베이스에 들어갔다는 점입니다. 이후 공식 제품·지원·법령 출처를 확인할 수 있는 한국어 자료로 문서를 다시 구성하고, 출처가 불명확한 고정 비용·조건은 근거로 제시하지 않도록 바꿨습니다.

### 답변·인용 검사

답변 가능 질문을 `demo.py --generate`로 실행할 때 세 질문 모두 생성 뒤 인용 존재 여부와 질문별 핵심 조건을 확인하도록 되어 있습니다. 연결 질문은 Galaxy Wearable 안내, 수영 후 질문은 헹굼·건조, 반품 질문은 `Refund Policy.md#2`의 기간과 예외가 답변 및 인용에 있는지 검사합니다. 생성 출력의 한 문장이 실제 인용 문장으로 뒷받침되는지 사람이 확인해야 하며, 자동 게이트 통과만을 사실 정확성 보증으로 보지 않습니다.

## 8. 핵심 발견과 한계

- 한국어 자료에서는 비교한 두 모델 중 다국어 임베딩이 기대 문서 Hit@3가 높아(8/8) 기본값으로 적절했습니다. 생성 LLM 교체는 하지 않았습니다.
- `0.25` 단독으로는 IN/OUT을 분리할 수 없었습니다. 점수가 높은 OUT 질문 세 개가 날짜·숫자·금액의 구체 근거를 갖지는 않았습니다.
- 의미 검색 뒤 질문이 요구한 값과 단위가 청크에 실제 있는지 확인해, 답변 불가 4/4를 LLM 호출 전에 차단했습니다.
- 게이트를 우회한 날짜 질문에 문서 밖 일반 안내가 섞여 나와, 생성 프롬프트만으로 근거 밖 보완을 완전히 막을 수 없음을 확인했습니다.
- IN 8개·OUT 4개는 소규모 평가입니다. 문자열 핵심어·정규식 기반 게이트는 동의어·복합 질문에서 오탐 또는 미탐이 날 수 있습니다. 질문 집합과 문서가 늘면 회귀 테스트를 확장해야 합니다.
- 과거 출처 불명 내용은 검색 컨텍스트 안에 있었으므로 당시 실패를 순수한 모델 지식 누출로 단정할 수 없습니다. 데이터 출처 검증을 우선 수정했습니다.

### 모델 선택에 관한 결론

이번 한국어 실습에서는 다국어 임베딩을 기본값으로 쓰는 것이 타당합니다. 같은 질의 묶음에서 한국어 기대 문서 검색이 더 안정적이었기 때문입니다. 다만 강의 지정 `all-MiniLM-L6-v2` 비교 결과도 재현할 수 있도록 모델 전환과 인덱스 재구축을 지원합니다. 생성 LLM은 4-1 코드 재사용이라는 실습 목표를 유지하기 위해 바꾸지 않았습니다. 생성 모델 변경은 별도 변수로 실험해야 하며, 검색 점수 개선의 근거로 섞어 설명하지 않습니다.

## 9. 재현 방법

프로젝트 루트에서 다음과 같이 실행합니다. 생성 시연을 하려면 Ollama 서버와 `llama3.2` 모델이 준비돼 있어야 합니다.

```bash
cd "MatchUP AI Native Cloud/4주차/코드/rag"
../../../../.venv/bin/python build_index.py
../../../../.venv/bin/python model_eval.py
../../../../.venv/bin/python demo.py
../../../../.venv/bin/python demo.py --generate
../../../../.venv/bin/python demo.py --ungated-probe
../../../../.venv/bin/python rag.py check "갤럭시 워치7의 다음 소프트웨어 업데이트 날짜는 언제인가요?"
```

강의 기본 임베딩과 비교하려면 선택한 모델로 인덱스를 다시 만들어야 합니다.

```bash
../../../../.venv/bin/python demo.py --model sentence-transformers/all-MiniLM-L6-v2 --rebuild
../../../../.venv/bin/python demo.py --model sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 --rebuild
```

모델 카드와 생성 모델 안내: [all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2), [다국어 MiniLM](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2), [Ollama llama3.2](https://ollama.com/library/llama3.2).
