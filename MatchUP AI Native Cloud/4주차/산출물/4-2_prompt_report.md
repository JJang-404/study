## 3. 프롬프트 설계 비교

### Zero-shot (`zero_shot.md`)
```
지시: "긍정/부정 분류"
출력 형식: {"label": "...", "confidence": ...}
예시: 없음
판단 기준: 없음
```
→ 모델이 스스로 "긍정/부정"의 기준을 해석해야 함

### Few-shot (`few_shot.md`)
```
지시: 동일
출력 형식: 동일
예시: 3개 (긍정 2 / 부정 1)
판단 기준: 3가지 명시
  ① 전반적 최종 만족도 기준 (배송 불만 + 제품 만족 → positive 가능)
  ② 반어·빈정거림 → 부정으로 해석
  ③ 결론이 만족이면 positive, 실망이면 negative
```
→ 경계 케이스 판단 기준을 미리 주입

### 왜 few-shot이 보통 더 나은 결과를 내는가

Zero-shot은 작업 지시만 보고 모델이 분류 기준과 출력 습관을 스스로 추론해야 합니다.
Few-shot은 지시와 함께 입력·정답 예시를 보여 주기 때문에, 모델이 예시의 패턴을 문맥 안에서
참고해 다음 리뷰에도 적용할 수 있습니다. 리뷰 감성 분류에서는 특히 다음 효과를 기대할 수 있습니다.

| Few-shot이 주는 정보 | 분류에서 기대하는 효과 |
|---------------------|------------------------|
| 각 감성의 구체적인 문장과 라벨 | positive·negative 라벨의 의미를 과제 맥락에 맞게 고정 |
| 배송 불만과 제품 만족이 함께 있는 예시 | 혼합 감정에서 어떤 단서를 우선할지 보여 줌 |
| 예시와 같은 JSON 출력 | 출력 모양과 필드 이름을 따라 파싱 실패를 줄임 |
| 도메인 어휘·표현의 사례 | 일반적인 감성 해석과 상품 리뷰의 판단 기준 차이를 알려 줌 |

즉, few-shot은 모델의 가중치를 다시 학습하는 방식은 아니지만, 현재 요청의 문맥 안에 작은 기준 사례를
제공해 답변의 기준과 형식을 맞추도록 돕습니다. 예시가 실제 입력을 잘 대표하고 서로 일관될수록
효과를 기대하기 쉽습니다. 반대로 예시가 틀렸거나 서로 충돌하거나 실제 리뷰와 동떨어지면,
모델이 잘못된 패턴을 따라 정확도가 떨어지거나 `netral`처럼 허용되지 않은 라벨을 낼 수도 있습니다.

이번 실험은 일반적인 경향을 검증할 만큼 크지 않습니다. 두 방식 모두 12개 중 12개를 맞혀
정확도 차이는 없었고, 이번 실행에서 few-shot의 평균 confidence는 0.883에서 0.936으로 높았습니다.
따라서 **이번 결과는 few-shot이 더 높은 확신을 보였다는 점은 보여 주지만, 정확도를 높였다고
증명하지는 않습니다.** 강사님 말씀은 예시가 유효하고 zero-shot이 놓치는 기준을 보완하는
일반적인 조건에서 기대되는 경향으로 이해하는 것이 정확합니다. 실제 개선 여부는 더 크고 다양한
검증 데이터에서 정확도와 오류 유형을 함께 비교해야 합니다.

**정확도 변화:** few-shot − zero-shot = **+0.0%p** (상대 변화 0.0%; 12/12에서 12/12, 변화 없음).
평균 confidence는 **+0.053** 상승했습니다. JSON 파싱은 응답 안에서 JSON 객체를 찾아 읽는 성공률이고,
엄격 파싱은 응답 전체를 추가 추출 없이 JSON 객체로 읽을 수 있는 비율입니다.
응답시간은 각 LLM 호출의 시작부터 응답 반환까지를 측정한 평균입니다.

> **정확도는 동일하지만 few-shot의 평균 confidence가 더 높았습니다.**  
> Few-shot 프롬프트가 모델을 더 확신 있게 판단하도록 유도했습니다.

### 허용되지 않은 라벨 출력 진단

강사님 시연에서는 few-shot 응답에 허용되지 않은 라벨 `netral`이 생성되어,
프롬프트 안의 상충하는 지시 중 잘못된 쪽을 따르는 문제가 있었다고 합니다.
저장된 이번 실험 결과 JSON의 모델 응답을 다시 확인한 결과는 다음과 같습니다.

| 확인 항목 | Zero-shot | Few-shot |
|-----------|-----------|----------|
| 확인한 응답 수 | 12 | 12 |
| 출력된 라벨 | `positive`, `negative` | `positive`, `negative` |
| 허용되지 않은 라벨 | 0건 | 0건 |
| JSON 파싱 실패 | 0건 | 0건 |

따라서 **현재 저장된 우리 실행 결과에서는 `netral` 같은 잘못된 라벨을 사용한 사례가 없습니다.**
강사님 시연의 오류는 이번 결과 JSON에 나타나지 않았으며, 모델·프롬프트·실행이 달라질 수 있어
그 시연과 동일한 현상이 재현되지 않았다고 해석하면 됩니다. 이 판정은 저장된 24개 응답에 한정됩니다.

분류 스크립트는 JSON 파싱 성공과 정답 일치를 별도로 기록합니다. 허용되지 않은 문자열 라벨이
정상 JSON 안에 들어오면 파싱은 성공하더라도 정답 라벨과 일치하지 않아 오분류로 계산됩니다.
이번 결과에서는 해당 상황도 없었습니다.

## 6. 주목할 패턴 분석

### 정답률과 confidence는 다르게 움직임

- 정확도는 두 방식 모두 100%여서 few-shot의 정확도 개선은 **0%p**입니다.
- 평균 confidence는 zero-shot 0.883에서 few-shot 0.936으로 **0.053 상승**했습니다.
- 12개 전부 정답이므로 이번 데이터에는 오답 사례가 없습니다. 따라서 특정 오답을 고친 효과는 관찰하지 못했습니다.

### 오답 분석

| 점검 항목 | zero-shot | few-shot |
|-----------|----------:|---------:|
| 오답 | 0건 | 0건 |
| 허용되지 않은 라벨 | 0건 | 0건 |
| JSON 파싱 실패 | 0건 | 0건 |

실제 오답이 없어 원인별 오분류 분석은 할 수 없습니다. 대신 confidence가 낮았던 5·10·11번을
후속 검토 대상으로 남깁니다. 특히 10번은 빠른 배송과 제품 불만이 섞인 경계 사례이고,
11번은 반어 표현이 포함돼 있습니다. 이 사례들의 기준 라벨과 판단 규칙을 더 분명히 한 뒤,
별도의 새 리뷰에서 개선되는지 확인하는 것이 다음 단계입니다.

### 리뷰별 confidence 변화

- 명확한 긍정/부정 8개 중 대부분에서 few-shot confidence가 0.05~0.09 높아졌습니다.
- 혼합 감정인 5번은 0.80 → 0.85로 소폭 상승했습니다.
- 10번 경계 사례는 0.80 → 0.81로 거의 변하지 않았습니다.
- 11번 반어 사례는 0.90 → 0.81로 오히려 낮아졌습니다. Few-shot이 언제나 confidence를 높이지는 않았습니다.
- 따라서 few-shot은 기준 사례를 제공해 판단을 돕지만, 효과 크기와 방향은 문항마다 다릅니다.

### 개선 분석

이번 실행만 보면 정확도 개선은 측정되지 않았습니다. 다음 비교에서는 명확한 문항보다 반어,
혼합 감정, 중립에 가까운 리뷰를 더 확보하고, zero-shot이 틀리고 few-shot이 맞힌 문항 수와
그 반대의 문항 수를 따로 집계해야 합니다. 예시는 평가 리뷰와 겹치지 않게 구성하고,
오류를 확인한 뒤 경계 사례를 보강하되 같은 데이터에만 맞춘 프롬프트가 되지 않도록
별도의 미사용 검증 리뷰에서도 개선이 유지되는지 확인하는 것이 좋습니다.

응답시간은 zero-shot 0.527초, few-shot 0.451초로 기록됐지만, zero-shot 첫 호출이 1.618초였고
이후 호출은 약 0.42초였습니다. 모델 로딩이나 워밍업 영향이 포함됐을 수 있으므로 이번 순차 실행만으로
few-shot이 더 빠르다고 결론 내릴 수 없습니다. 공정한 속도 비교에는 두 프롬프트의 실행 순서를
바꿔 반복 측정하고 첫 호출 워밍업을 별도로 처리해야 합니다.

## 7. 한계 및 솔직한 평가

### 이 실험에서 말할 수 있는 것

- 두 방식 모두 정확도 100% (12/12), JSON 파싱·엄격 파싱 100%입니다.
- few-shot 평균 confidence는 0.936으로 zero-shot의 0.883보다 0.053 높았습니다.
- few-shot의 confidence는 5번에서 0.05 상승, 10번에서 0.01 상승, 11번에서 0.09 하락했습니다.
- **오답이 없어 과신으로 인한 오분류는 관찰되지 않았습니다.**

### 과신 오류 분석

과신 오류를 "confidence가 0.90 이상인데 예측 라벨이 틀린 경우"로 정의했습니다.

| 프롬프트 | confidence ≥ 0.90인 문항 | 그중 오답 |
|----------|---------------------------:|----------:|
| zero-shot | 10 | 0 |
| few-shot | 9 | 0 |

이번 결과에서는 두 방식 모두 고 confidence 오답이 없습니다. 다만 리뷰가 12개뿐이고 모두 정답이라,
이 결과만으로 confidence가 실제 정답 확률과 잘 맞는다고 평가할 수 없습니다. confidence는 모델이
직접 출력한 자기평가 수치이며, 더 많은 정답·오답 사례를 포함해 별도로 보정 상태를 확인해야 합니다.

### 이 실험의 한계

| 한계 | 설명 |
|------|------|
| **데이터 12개** | 너무 적어 정확도 차이가 안 나올 가능성 높음 |
| **accuracy 100% 동일** | 두 방식의 "정확도 차이"를 보여주려면 더 어려운 리뷰 필요 |
| **모델 1개** | 다른 모델에서 같은 결과가 나오는지 비교하지 않음 |
| **confidence는 주관적 수치** | 모델이 "0.9라고 출력"해도 실제 확신과 다를 수 있음 |

### 언제 정확도 차이가 나타나나?

이번처럼 쉬운 문항에서 두 방식이 모두 만점을 받으면 정확도 차이를 관찰할 수 없습니다.
더 다양한 경계 사례를 충분히 포함하고, 정답 기준을 사전에 고정한 검증 데이터에서 비교해야 합니다.
필요 데이터 수는 기대 효과와 변동성에 따라 정해야 하며, 이 12개만으로 일반화할 수 없습니다.

## 8. 실무 지침

### 언제 zero-shot으로도 충분한가

- 신호가 명확한 텍스트 (욕설, 극찬, 환불 요청 등)
- 도메인이 단순하고 경계 케이스가 드문 경우
- 빠른 프로토타입이 필요한 경우

### 언제 few-shot을 써야 하는가

| 상황 | few-shot이 필요한 이유 |
|------|----------------------|
| 반어·빈정거림이 많은 리뷰 | 판단 기준과 예시를 제공해 경계 사례 대응을 유도할 수 있음. 이번 11번에서는 confidence가 0.90에서 0.81로 낮아졌고 정확도는 둘 다 정답 |
| 혼합 감정 리뷰 | "어느 쪽이 우선인가" 기준 필요 |
| 도메인 특화 어휘 | 업계 특수 표현은 예시 없으면 오해 가능 |
| confidence threshold 기반 자동화 | few-shot confidence도 정답 확률과 같다고 볼 수 없으므로, 별도 검증·보정 후 기준 설정 |

### 프롬프트 설계 원칙 (이번 실험 근거)

```
1. temperature=0 고정 — 분류·추출은 결정적 결과 필요 (실험 설정)
2. 출력 형식 명시 — JSON only 지시 → 파싱 성공률 100% 유지
3. 판단 기준 3가지 — 경계 케이스를 예측하고 미리 규칙화
4. 예시는 긍정 2 / 부정 1 — 평가할 실제 업무와 가까운 사례를 선택
5. 자주 틀리는 경계 사례를 보강하되, 검증용 리뷰와 예시가 겹치지 않게 구성
```
