### 실습 3-1. 견고한 API 호출 클라이언트 구현 — 재시도·백오프·타임아웃 (슬라이드 13)

**실습 목표**: 운영 수준의 견고성 패턴(robustness pattern)을 갖춘 재사용 가능한 API 호출 클라이언트를 설계·구현하고, 재시도 동작을 단위 테스트로 정규 검증한다. 3주차 데이터 파이프라인(수집 단계)에서 재사용할 기반 모듈을 만든다.

**왜 필요한가**: 외부 API/LLM 호출은 일시적 장애(타임아웃·5xx·레이트리밋·네트워크 끊김)가 잦습니다. 지수 백오프 + 지터 재시도로 일시 장애는 자동 복구하고, 영구 실패(4xx)는 즉시 중단해 불필요한 재시도를 막는 것이 핵심입니다.

💬 **Claude Code 프롬프트 (견고한 호출 클라이언트 + 테스트)**

> <br/>
> 데이터 파이프라인의 "수집" 단계에서 재사용할 견고한 HTTP 호출 모듈을 실습산출물/3주차/robust_client.py 로 만들어줘(폴더 없으면 생성).<br/>
> requests 기반이고 다음 요구사항을 정확히 지켜:<br/>
> [함수 설계]<br/>
> * `call_api(url, method="GET", payload=None, headers=None, timeout=5.0, max_retries=3)` 시그니처<br/>
> * 재시도 대상(일시 장애): 연결 오류, 읽기 타임아웃, HTTP 429, HTTP 5xx<br/>
> * 재시도 제외(영구 실패): HTTP 4xx(429 제외)는 즉시 예외로 중단<br/>
> * 지수 백오프 + 지터: 대기 = `base(1s) * 2**(attempt-1) + random(0~0.5s)`, 상한 10s<br/>
> * 429 응답에 Retry-After 헤더가 있으면 그 값을 우선 적용<br/>
> * 각 시도/대기/실패 사유를 logging(레벨 INFO/WARNING)으로 남기고, 최종 실패 시 마지막 원인을 포함한 커스텀 예외(ApicallError)를 던져<br/>
> * 성공 시 파싱된 JSON(dict)을 반환<br/>
>
> [테스트]<br/>
> 실습산출물/3주차/tests/test_robust_client.py 를 pytest + unittest.mock(또는 responses)로 작성해:<br/>
> `1) 2회 5xx 실패 후 3회차 200 성공 -> 반환값 검증 + 재시도 2회 발생 확인`<br/>
> `2) 3회 모두 타임아웃 -> ApiCallError 발생 확인`<br/>
> `3) 404(영구 실패) -> 재시도 없이 즉시 예외 확인`<br/>
> `4) 429 + Retry-After=2 -> 지정 지연 후 재시도 확인`<br/>
>
> 백오프 sleep은 mock으로 대체해 테스트가 실제로 기다리지 않게 하고, 실행해서 4개 케이스가 모두 통과하는지 결과를 보여줘.<br/>

실행 방법

```bash
pip install -U requests pytest   # 미설치면 신규 설치, 있으면 업그레이드
pytest -q 실습산출물/3주차/tests/test_robust_client.py
```

☑ 검증: `robust_client.py`가 재시도 대상/제외를 구분하고 지수 백오프+지터로 대기하며, 4개 테스트 케이스(성공-후-재시도 / 전체 실패 / 4xx 즉시중단 / 429 Retry-After)가 모두 통과한다.

### 실습 3-2. RAG 전처리 파이프라인 구축 — 파싱 → 청킹 → 임베딩 → 유사도 검색 (슬라이드 28-39 통합)

실습 목표: 문서 한 건이 검색 가능한 지식이 되기까지의 RAG 전처리 전 과정을 하나의 연결된 파이프라인으로 구축한다. ① 문서를 파싱하고 → ② 의미 단위로 청킹하고 → ③ 각 청크를 임베딩해 인덱스로 저장하고 → ④ 질의를 같은 공간에 임베딩해 코사인 유사도로 top-k를 검색한다.

>스토리 흐름: 원본 문서 -> (parse) 텍스트 -> (chunk) 조각 -> (embed) 벡터 인덱스 -> (search) 질의로 top-k 회수. 각 단계의 출력이 다음 단계의 입력이 되는 데이터 흐름을 그대로 코드로 옮깁니다. 이 파이프라인이 4주차 RAG의 "검색" 부분 토대가 됩니다.

💬 **Claude Code 프롬프트 (파싱→청킹→임베딩→검색 파이프라인)**

> 문서를 검색 가능한 지식으로 만드는 RAG 전처리 파이프라인을 실습산출물/3주차/rag_prep/ 아래에 모듈로 나눠 만들어줘(폴더 없으면 생성). 각 단계는 재사용 가능한 함수로 분리해.
>
> [1단계 · 파싱] parser.py
> * `parse_document(path)->str` : PDF는 pypdf로, .txt/.md는 그대로 읽어 정규화(중복 공백·개행 정리)한 텍스트 반환
> * 테스트용 샘플 문서가 없으면 더미 문서(`실습산출물/3주차/rag_prep/sample.txt`)를 만들어 사용
> 
> 
> [2단계 · 청킹] chunker.py
> * `chunk_text(text, size=500, overlap=50)->list[dict]` : 각 청크에 {id, text, start, end} 메타를 붙여 반환
> * 실행 시 청크 수·평균 길이·첫 2개 미리보기(앞 80자)를 출력
> 
> 
> [3단계 · 임베딩/인덱싱] indexer.py
> * `sentence-transformers(all-MiniLM-L6-v2)`로 청크들을 임베딩하고, 벡터+메타를 실습산출물/3주차/rag_prep/index.npz(또는 json+npy)로 저장
> * `build_index(chunks)`와 `load_index()`를 분리, 임베딩 차원·인덱싱 소요 시간 출력
> 
> 
> [4단계 · 검색] search.py
> * `search(query, top_k=3)` : 질의를 같은 모델로 임베딩해 코사인 유사도 top-k 청크를 (점수, 청크 텍스트, 출력 id)로 반환
> * 실행 시 인자로 받은 질의에 대해 상위 3개 결과와 검색 소요 시간을 출력
>
> 이미지 속 내용을 마크다운으로 변환한 텍스트입니다. 유저 설정에 따라 마크다운 문법을 렌더링하지 않고 원본 코드로 제공합니다.
>
> [파이프라인 오케스트레이션] pipeline.py
> - 파싱->청킹->인덱싱을 한 번에 실행하는 build(path)와, 질의를 받는 query(q) 제공
> - 끝에 파이프라인 각 단계 산출물(청크 수, 인덱스 크기, 예시 검색 결과)을 요약해 실습산출물/3주차/3-2_rag_pipeline_report.md 로 저장
>
> 마지막에 sample 문서로 build 후 "핵심 개념 한 줄" 같은 질의로 검색을 시연해 top-3 결과를 보여줘.

⚙ 실행 방법

```bash
pip install -U pypdf sentence-transformers numpy   # 미설치면 신규 설치, 있으면 업그레이드
python 실습산출물/3주차/rag_prep/pipeline.py build 실습산출물/3주차/rag_prep/sample.txt
python 실습산출물/3주차/rag_prep/pipeline.py query "질의 문장"

```

검증: 파싱→청킹→임베딩→검색이 순차 연결되어 동작하고, `index.npz`(벡터 인덱스)와 `3-2_rag_pipeline_report.md` 가 생성되며, 질의에 대해 코사인 유사도 top-3 청크가 점수·출처와 함께 반환된다. (다음 주차: RAG "생성" 단계로 연결)
