|------|------|

### 전체 흐름 한눈 정리

```
[실습 3-1] 견고한 HTTP 호출
  └─ call_api()
       ├─ 일시 장애 (5xx / 429 / ConnectionError / ReadTimeout)
       │    └─ 지수 백오프 + 지터 → 재시도 (최대 max_retries회)
       └─ 영구 실패 (4xx, 429 제외) → 즉시 ApiCallError

[실습 3-2] RAG 전처리 파이프라인
  문서(PDF/txt/md)
    │
    ▼ [1단계] 파싱 (parser.py)
  정규화 텍스트 (5,966자)
    │
    ▼ [2단계] 청킹 (chunker.py)
  청크 리스트 14개 (size=500, overlap=50)
    │
    ▼ [3단계] 임베딩·인덱싱 (indexer.py)
  index.npz (14×384 float32, L2 정규화 norm=1.000000)
    │
    ▼ [4단계] 검색 (search.py)
  top-k 청크 반환 (hybrid: BM25 n-gram + semantic → RRF)
```

## 2. 실습별 요약 표

### 실습 3-1 · 견고한 API 호출 클라이언트

| 항목 | 내용 |
|------|------|
| 목표 | 네트워크·서버 오류를 자동 복구하는 재사용 가능한 HTTP 클라이언트 모듈 |
| 핵심 함수 | `call_api(url, method, payload, headers, timeout, max_retries)` |
| 핵심 예외 | `ApiCallError` — 영구 실패 또는 최대 재시도 초과 시 발생 |
| 재시도 대상 | ConnectionError, ReadTimeout, HTTP 429, HTTP 5xx |
| 영구 실패 | HTTP 4xx (429 제외) → 즉시 raise, sleep 없음 |
| 대기 공식 | `min(1s × 2^(attempt-1) + random(0~0.5s), 10s)` |
| 429 특수 처리 | `Retry-After` 헤더 값이 있으면 그 시간만큼 대기 (백오프 공식 무시) |
| 로깅 | INFO(시도), WARNING(재시도), ERROR(최종 실패) |
| 산출물 파일 | `3주차/코드/robust_client.py` |
| 검증 결과 | pytest 4/4 통과 |

**테스트 케이스 4종**

| 케이스 | 시나리오 | 기대 결과 |
|--------|---------|---------|
| 1 | 5xx × 2 후 200 성공 | 반환값 OK + 재시도 2회 확인 |
| 2 | ReadTimeout × 3 | ApiCallError 발생 |
| 3 | 404 즉시 | 재시도 없이 ApiCallError |
| 4 | 429 + Retry-After=2 | sleep(2.0) 정확히 1회 호출 |

## 4. 핵심 개념 정리

### 4-1. 지수 백오프 + 지터 재시도

```
대기 시간 = min(base × 2^(attempt-1) + random(0, 0.5), max_wait)
           = min(1s × 2^(n-1) + 지터, 10s)
```

| 시도 | 기본 대기 | 지터 포함 (예시) |
|------|---------|--------------|
| 1회 | 1s | 1.23s |
| 2회 | 2s | 2.41s |
| 3회 | 4s | 4.18s |
| 이후 | 상한 10s | 10s |

- **지터(jitter)**: 동시에 많은 클라이언트가 재시도할 때 충돌하는 "Thundering Herd" 문제 방지
- **Retry-After 헤더**: 429 응답에서 서버가 대기 시간을 지정하면 공식 무시, 서버 지정 시간 우선

### 4-2. 일시 장애 vs 영구 실패

| 구분 | 해당 상황 | 처리 |
|------|---------|------|
| 일시 장애 | 5xx, 429, ConnectionError, ReadTimeout | 재시도 → 최대 횟수 초과 시 ApiCallError |
| 영구 실패 | 4xx (429 제외): 400, 401, 403, 404 등 | 즉시 ApiCallError, 재시도 없음 |

### 4-3. 문서 파싱과 오버랩 청킹

- **파싱**: 원본 파일(PDF/txt/md) → 정규화 텍스트 (공백·개행 통일, 탭 제거)
- **슬라이딩 윈도우 청킹**: `size=500, overlap=50`
  - 각 청크는 `start/end` 오프셋으로 원본에서의 위치 추적 가능
  - 오버랩 50자: 청크 경계에서 문맥이 잘리는 것을 방지
  - 14개 청크 → top-3 검색 = 전체의 21% (의미 있는 변별력)

### 4-4. 임베딩 · 코사인 유사도 · 벡터 인덱스

**임베딩**
- 텍스트를 고차원 벡터(384차원)로 변환 — 의미적으로 유사한 텍스트는 벡터 공간에서 가까운 위치
- 다국어 모델 선택 이유: 영어 전용 모델(`all-MiniLM-L6-v2`)로 한국어 테스트 시 치명적 품질 문제 발견
  - 한↔영 같은 의미 유사도: -0.008 (사실상 0)
  - 한↔한 다른 주제 유사도: 0.73 (오탐)

**코사인 유사도**
```
cosine(A, B) = (A · B) / (|A| × |B|)
```
- 벡터의 방향(의미)만 비교, 크기(magnitude)는 무시
- L2 정규화 후: `cosine(A, B) = A · B` (dot product만으로 계산 가능, 더 빠름)

**벡터 인덱스 (`index.npz`)**

| 배열 | dtype | shape | 설명 |
|------|-------|-------|------|
| `vectors` | float32 | (14, 384) | L2 정규화 임베딩 (norm=1.000000) |
| `ids` | int32 | (14,) | 청크 순번 |
| `texts` | object | (14,) | 청크 본문 |
| `starts` | int32 | (14,) | 원본 텍스트 시작 오프셋 |
| `ends` | int32 | (14,) | 원본 텍스트 종료 오프셋 |

### 4-5. 하이브리드 검색 (Hybrid RAG)

| 검색 방식 | 원리 | 강점 |
|---------|------|------|
| 시맨틱 | 임베딩 벡터 dot product | 동의어·패러프레이즈 검색 |
| BM25 | 키워드 빈도 기반 | 정확한 용어 매칭 |
| **RRF 융합** | `1/(k + rank)` 합산 | 두 방식의 상호 보완 |

**한국어 BM25 주의사항**: 공백 분리만으로는 어미 결합 토큰 매칭 실패 (`재시도해도` ≠ `재시도`).  
→ 문자 2-gram 추가로 부분 매칭 보완. 완전 해결은 KoNLPy 등 형태소 분석기 필요.

## 5. 4주차 연결 포인트

3주차에서 구축한 RAG 파이프라인은 **"검색(Retrieval)"** 단계까지입니다.  
4주차에서는 **"생성(Generation)"** 단계를 추가해 완전한 RAG를 완성합니다.

```
[3주차 완성] 검색까지
  query("지수 백오프란?")
    └─ search() → top-k 청크 리스트 반환

[4주차 추가] 생성 단계
  top-k 청크
    └─ 프롬프트 조립 (시스템 메시지 + 컨텍스트 + 질의)
         └─ LLM API 호출 (OpenAI / Azure OpenAI / Claude)
              └─ 최종 답변 생성
```

**4주차 구현 포인트**

| 항목 | 내용 |
|------|------|
| 프롬프트 설계 | 검색된 청크를 `[컨텍스트]` 블록으로 삽입하는 템플릿 |
| LLM 연결 | `pipeline.py`의 `query()` 반환값을 OpenAI/Anthropic API로 전달 |
| 할루시네이션 방지 | "제공된 문서에 없으면 모른다고 답하라" 지시 추가 |
| 평가 지표 | Faithfulness (출처 일치), Relevance (질문 관련성), RAGAS 프레임워크 |
| 개선 방향 | 청크 수 확대, 리랭킹(cross-encoder), 메타데이터 필터링 |

**연결 코드 예시 (4주차 스타터)**

```python
from rag_prep.pipeline import query as rag_query
import anthropic

def answer(question: str) -> str:
    chunks = rag_query(question, top_k=3)
    context = "\n\n".join(f"[청크{c['id']}] {c['text']}" for c in chunks)
    
    client = anthropic.Anthropic()
    msg = client.messages.create(
        model="claude-sonnet-4-5",
        max_tokens=1024,
        messages=[{
            "role": "user",
            "content": f"다음 문서를 참고해 질문에 답하세요.\n\n{context}\n\n질문: {question}"
        }]
    )
    return msg.content[0].text
```
