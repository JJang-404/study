## 개념 정리 · MCP (Model Context Protocol)

### 1. 정의

AI 모델이 외부 도구와 데이터에 접근하는 방식을 표준화한 **오픈 프로토콜**.
Anthropic이 2024년 11월 공개했으며 현재 업계 표준으로 자리 잡았다.

### 2. 왜 필요한가

> **USB-C 비유** — 포트가 하나로 통일되기 전에는 기기마다 전용 케이블이 필요했다.

| 구분 | MCP 이전 | MCP 이후 |
|---|---|---|
| 연동 비용 | N개 모델 × M개 도구 = **N×M** | **N+M** |
| 예시 | Claude용 Slack 연동, GPT용 Slack 연동을 각각 제작 | Slack MCP 서버 하나 → 모든 MCP 클라이언트가 사용 |

### 3. 구조

```
┌──────────────────┐        ┌────────────┐        ┌──────────────┐
│   MCP 클라이언트   │◀─MCP──▶│  MCP 서버  │◀──────▶│   실제 대상   │
│  (Claude Code,   │        │  (어댑터)   │        │  DB, API,    │
│   Claude Desktop)│        │            │        │  파일시스템    │
└──────────────────┘        └────────────┘        └──────────────┘
```

| 구성 요소 | 설명 |
|---|---|
| **Host** | AI 애플리케이션 (Claude Desktop, Claude Code, VS Code 등) |
| **Client** | Host 안에서 서버 하나와 1:1 연결을 맡는 부분 |
| **Server** | 특정 기능을 노출하는 독립 프로세스 |

### 4. 서버가 제공하는 3가지 기본 요소

| 종류 | 제어 주체 | 설명 | 예시 |
|---|---|---|---|
| **Tools** | 모델 | 모델이 호출하는 동작(함수) | `send_email`, `query_db` |
| **Resources** | 애플리케이션 | 모델이 읽는 데이터 | 파일 내용, DB 스키마 |
| **Prompts** | 사용자 | 미리 정의된 프롬프트 템플릿 | "이 코드 리뷰해줘" |

> **핵심 구분:** Tools는 **모델이 스스로 판단해 호출**하고, Resources는 애플리케이션이 컨텍스트로 넣어주며, Prompts는 사용자가 선택해 실행한다.

### 5. 전송 방식 (Transport)

| 방식 | 용도 | 특징 |
|---|---|---|
| **stdio** | 로컬 프로세스 | 표준입출력으로 통신. 설정 간단, 로컬 전용 |
| **Streamable HTTP** | 원격 / 클라우드 | HTTP 기반. 인증(OAuth) 필요, 여러 사용자 공유 가능 |

메시지 형식은 양쪽 모두 **JSON-RPC 2.0**.

### 6. 클라우드 연동 갈래

| # | 갈래 | 방법 |
|---|---|---|
| 1 | **SaaS 커넥터** (Gmail, Drive, Notion, Slack) | 제공된 원격 MCP 서버에 OAuth 인증만 하면 됨 |
| 2 | **클라우드 플랫폼** (AWS, GCP, Azure) | 공식 MCP 서버 + 자격증명(credential) 설정 |
| 3 | **직접 제작** | Python `pip install mcp` / Node `npm i @modelcontextprotocol/sdk` |

### 7. 참고

- 공식 문서: <https://modelcontextprotocol.io>
- 스펙: <https://spec.modelcontextprotocol.io>

## 실습 1-1 · Claude Desktop 설치 & MCP 3종 등록

**실습 목표**
Claude Desktop을 설치(또는 업그레이드)하고, MCP 설정 파일을 생성한 뒤 **요즘 가장 많이 쓰이는 MCP 3종**을 한 번에 등록한다.

### 등록할 MCP 3종

모두 `npx`로 별도 설치 없이 실행된다 (Node.js 18+ 필요). Claude Desktop·Claude Code 양쪽에서 사용 가능하다.

| MCP | 제공 | 무엇을 하나 | 패키지 |
|---|---|---|---|
| **Context7** | Upstash | 라이브러리·프레임워크의 최신 공식 문서/예제를 실시간 주입 (환각 방지) | `@upstash/context7-mcp` |
| **Sequential Thinking** | Anthropic (MCP 공식) | 복잡한 문제를 **단계적 사고(reasoning)** 체인으로 분해 | `@modelcontextprotocol/server-sequential-thinking` |
| **Playwright** | Microsoft | 실제 브라우저를 구동해 **웹 탐색·스크래핑·E2E 자동화** | `@playwright/mcp` |

### 사전 준비 (Node.js)

```powershell
node -v; npx -v
# v22.19.0
# 10.9.3
```

### 💭 Claude Code 프롬프트 — 설정 파일 생성 + MCP 3종 등록 통합

```text
내 Windows 환경에서 Claude Desktop의 MCP 설정 파일 경로(`$env:APPDATA\Claude\claude_desktop_config.json`)를
확인하고, 파일이 없으면 빈 mcpServers 객체를 가진 기본 JSON으로 새로 생성해줘.

이어서 그 mcpServers에 아래 3개 MCP 서버를 "아직 등록되지 않은 것만" 병합해서 추가하고,
이미 같은 이름(key)이 있으면 건드리지 말고 건너뛰어:
(1) context7            -> command "npx", args ["-y","@upstash/context7-mcp"]
(2) sequential-thinking -> command "npx", args ["-y","@modelcontextprotocol/server-sequential-thinking"]
(3) playwright          -> command "npx", args ["-y","@playwright/mcp@latest"]

기존 mcpServers 항목은 절대 덮어쓰지 말고 보존하고(변경이 없으면 파일을 다시 쓰지 마),
Windows에서는 npx가 npx.cmd여야 할 수 있음을 안내해줘.

마지막에 서버별 "추가됨/이미 존재해서 건너뜀"을 표로 알려주고 최종 파일 내용을 출력한 뒤,
이 설정 과정을 정리한 메모를 실습산출물/1주차/1-1_mcp_setup.md로 저장해줘(폴더 없으면 생성).
```

### ✅ 정상 구동 확인 프롬프트

**MCP 확인 시에는 Opus 5 이상 모델로 진행한다.**

```text
세 개의 신규 MCP 를 활용할 수 있도록 모두 승인해주세요.
승인 후 정상적으로 세 개의 MCP가 구동하는지 확인 후 정상 여부를 출력해주세요
```

#### ① Context7 동작 확인

```text
Context7로 "Next.js 15의 App Router에서 서버 액션(server actions) 사용법"의 최신 공식 문서를
가져와서 핵심 예제 코드와 함께 3줄로 요약해줘. 어떤 라이브러리 문서를 참조했지도 표시해줘.
```

→ 모델 자체 지식이 아니라 **실시간으로 가져온 최신 문서를 인용**하면 정상.

#### ② Sequential Thinking 동작 확인

```text
Sequential Thinking 도구를 사용해서 "사과 3개와 바구니 2개가 있고 각 바구니에 같은 수로
나눠 담되 1개가 남는 경우의 수"를 단계별 사고로 분해해 풀어줘. 각 사고 단계가 출력되도록 해줘.
```

→ `Thought 1 → Thought 2 → ...` 형태의 **단계적 추론 로그**가 보이면 정상.

#### ③ Playwright 동작 확인

```text
Playwright MCP로 https://example.com 페이지를 열어 페이지 제목(title)과 본문 첫 문단 텍스트를
추출해서 보여줘. 브라우저가 처음이면 필요한 브라우저 바이너리 설치도 진행해줘.
```

→ 실제 브라우저를 열고 제목 `Example Domain` 등을 추출하면 정상.

#### Claude Desktop 설정과의 차이

| 구분 | Claude Desktop | Claude Code |
|---|---|---|
| 설정 위치 | `%APPDATA%\Claude\claude_desktop_config.json` | `claude mcp add` / `~/.claude.json` |
| 확인 방법 | 설정 → 개발자 → MCP | `claude mcp list` |
| 이번 실습 등록 | context7, sequential-thinking, playwright | (별도) 원격 커넥터 5종 + 플러그인 1종 |

> 두 호스트는 **MCP 설정을 공유하지 않는다.** 같은 서버를 양쪽에서 쓰려면 각각 등록해야 한다.

#### 전송 방식 비교 — 실측 확인

| 방식 | 이번 목록의 예 | 특징 |
|---|---|---|
| **stdio** | `plugin:oh-my-claudecode:t` | 로컬 프로세스를 `node`로 띄워 표준입출력으로 통신. 설정 간단, 인증 불필요 |
| **Streamable HTTP** | Gmail, Drive, Calendar, Notion, Claude Docs | 원격 서버에 HTTP로 접속. **OAuth 인증 필요** → 미인증 시 `Needs authentication` |

#### Notion 인증 처리

`Needs authentication`은 서버 등록은 됐지만 OAuth 승인이 안 된 상태다. 대화형 세션에서 `/mcp`를 실행해 Notion 항목을 선택하거나, claude.ai 웹의 커넥터 설정에서 직접 승인한다.

### 📌 배운 점

- MCP 서버는 호스트(Desktop / Code)별로 따로 등록·관리된다.
- 원격 MCP 서버는 **"등록됨"과 "사용 가능"이 다르다.** OAuth 승인까지 끝나야 도구가 실제로 노출된다.
- `claude mcp list`의 상태 기호(`✔` / `!`)로 연결 문제와 인증 문제를 한 번에 구분할 수 있다.

## 실습 1-4 · 로컬 Ollama 다중 모델 비교 & 라우팅

> 슬라이드 36·37·38

**실습 목표**
로컬 PC의 Ollama가 제공하는 여러 오픈 모델을 동일 프롬프트로 호출·비교하고, 작업 성격에 맞춰 모델을 라우팅해 활용한다.
외부 유료 API 대신 **로컬 모델만 사용** → 무료·오프라인.

### 💭 Claude Code 프롬프트

```text
로컬 Ollama가 제공하는 여러 모델을 비교·활용하는 실습이야.
모두 OpenAI 호환 엔드포인트(http://localhost:11434/v1)만 사용해(외부 유료 키 없이).

[1단계 · 사용 가능한 로컬 모델 확인]
ollama list로 현재 받아둔 모델을 확인하고, 비교에 쓸 모델이 부족하면
gpt-oss:20b, llama3.2, qwen2.5 중 없는 것만 ollama pull 로 받아줘(대략 3종).

[2단계 · 동일 프롬프트 다중 모델 비교]
같은 질문 "RAG를 한 줄로 설명"을 위 로컬 모델들에 각각 보내고,
각 모델의 응답 텍스트·응답 지연(latency, 초)·응답 길이(문자 수)를 측정해
모델별 한 행씩 표로 정리하는 compare_ollama.py를 만들어줘.
키는 OPENAI_API_KEY=ollama 로 두고, 호출 실패 시 해당 행에 에러를 표시하고 계속 진행하게 해.

[3단계 · 용도별 라우팅]
작업 성격에 따라 로컬 모델을 라우팅하는 pick_model(task) 함수를 router.py에 만들어줘.
규칙은 simple(간단 요약)→가장 가벼운 모델, code(코드 생성)→코드 특화/큰 모델, 그 외→기본 모델.
```
