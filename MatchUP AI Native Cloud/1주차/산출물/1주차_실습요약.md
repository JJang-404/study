### 1-2. 실습의 전체 흐름

교안의 3개 주제를 **실제로 돌아가는 환경**으로 구현하는 과정이었다.

```
[도구 셋업]          [클라우드 확인]        [로컬 모델 + MCP]
1-1 MCP 3종 등록  →  1-2 Azure CLI     →  1-3 GPT-OSS 실행
   context7             koreacentral         Ollama + 요약 생성
   sequential-thinking  가용 서비스 조회       filesystem MCP
   playwright
                              ↓
        [모델 선택]                    [개발 파이프라인]
   1-4 다중 모델 비교·라우팅     →     1-5 venv·.env·재시도·스트리밍
       gemma3 / qwen2.5 / llama3.2      견고한 호출 구조
```

**흐름의 논리:** 도구를 붙이고(1-1) → 클라우드 자원을 확인하고(1-2) → 로컬 모델을 돌려보고(1-3) → 어떤 모델을 쓸지 정하고(1-4) → 실무에 쓸 수 있는 구조로 다듬는다(1-5).

### 1-3. 이번 주차의 설계 선택 — 로컬 우선

모든 LLM 호출을 **로컬 Ollama의 OpenAI 호환 엔드포인트**(`http://localhost:11434/v1`)로 처리했다. 외부 유료 API 키 없이 진행하면서도 OpenAI SDK 코드 구조는 그대로 익힐 수 있다.

> 엔드포인트와 모델명을 `.env`로 분리했으므로, 나중에 실제 OpenAI나 Azure OpenAI로 전환할 때 **코드 수정 없이 설정만 바꾸면 된다.**

## 4. 배운 핵심 개념

### 4-1. MCP (Model Context Protocol)

AI 모델과 외부 도구·데이터를 연결하는 **표준 프로토콜**. N개 모델 × M개 도구의 조합 폭발(N×M)을 **N+M**으로 줄인다.

| 구성 요소 | 설명 |
|---|---|
| **호스트** | Claude Desktop, Claude Code 등 — MCP 서버를 띄우고 사용하는 쪽 |
| **서버** | 독립 프로세스로 기동되어 도구를 제공 |
| **Transport** | `stdio`(로컬 프로세스, 인증 불필요) / `Streamable HTTP`(원격, OAuth 필요) |

**실습으로 확인한 사실:** 호스트별로 설정이 **독립**이다. Claude Desktop에 등록해도 Claude Code에는 반영되지 않는다. 같은 서버를 양쪽에서 쓰려면 각각 등록해야 한다.

### 4-2. 로컬 오픈모델 (Local Open Models)

Ollama로 모델을 로컬에서 직접 실행. 데이터가 외부로 나가지 않고 오프라인에서도 동작한다.

**하드웨어가 곧 설계 제약이다.**

| 구조 | 특징 | 13 GB 모델 적재 |
|---|---|---|
| 분리형 메모리 (Windows + 외장 GPU) | RAM과 VRAM이 물리적으로 분리 | ❌ VRAM 6 GB 초과 → GPU/CPU 분할, PCIe 왕복이 병목 |
| 통합 메모리 (Apple Silicon) | CPU·GPU가 같은 메모리 풀 공유 | ✅ 24 GB 중 상당 부분을 GPU가 직접 사용 |

이 차이 때문에 **플랫폼별로 다른 모델을 쓰기로 결정**했다 (Windows `gemma3:12b` / macOS `gpt-oss:20b`).

### 4-3. OpenAI 호환 API

Ollama는 OpenAI와 동일한 `/v1/chat/completions` 인터페이스를 제공한다. 덕분에 **openai SDK 코드를 그대로 쓰면서 로컬 모델을 호출**할 수 있다.

```python
client = OpenAI(
    base_url="http://localhost:11434/v1",  # 여기만 바꾸면 로컬 ↔ 클라우드 전환
    api_key="ollama",                      # Ollama는 검증하지 않는 더미 값
)
```

> **이것이 설정을 `.env`로 분리하는 실질적 이유다.** 학습은 무료 로컬 모델로 하고, 운영은 클라우드 모델로 — 코드 수정 없이 전환된다.

### 4-4. 모델 라우팅 (Model Routing)

작업 성격에 따라 적합한 모델을 선택하는 패턴. 비용과 지연을 줄이면서 품질을 유지하는 것이 목적이다.

```python
ROUTING_TABLE = {
    "simple":  ("qwen2.5",    "최소 품질선을 넘는 가장 가벼운 모델"),
    "code":    ("qwen2.5",    "코드 생성 품질이 가장 좋음"),
    "general": ("gemma3:12b", "한국어 품질 우선"),
}
```

**실습에서 초기 규칙이 틀렸음을 발견했다.** 처음엔 `simple → 가장 가벼운 모델(llama3.2)`로 설계했으나 오답이 나왔다.

> **출력 길이와 필요 지식량은 별개 축이다.** "RAG를 한 줄로 설명"은 출력이 짧을 뿐, RAG 개념을 정확히 알아야 답할 수 있다. 라우팅의 첫 기준은 "가벼움"이 아니라 **"해당 언어·도메인에서 최소 품질선을 넘는가"**이고, 그 선을 통과한 모델 중에서 가벼운 것을 고르는 순서가 맞다.

### 4-5. 재시도 (Retry) · 스트리밍 (Streaming)

**지수 백오프 재시도** — 실패 시 대기 시간을 지수적으로 늘리며 재시도한다.

| 설계 요소 | 이유 |
|---|---|
| 지수 증가 (1초 → 2초 → 4초) | 일시적 과부하라면 시간을 줄수록 회복 가능성이 높아진다 |
| 지터(jitter) 추가 | 고정 간격이면 여러 클라이언트의 재시도가 같은 시점에 몰린다 |
| 4xx 제외 | 잘못된 요청은 재시도해도 결과가 같다. 429와 5xx만 재시도 |
| `max_retries=0` | SDK 자체 재시도를 꺼야 한다. 안 그러면 **이중으로 걸려 3회가 9회가 된다** |

**스트리밍** — 토큰이 도착하는 즉시 출력해 체감 대기 시간을 줄인다.

```python
for chunk in stream:
    if not chunk.choices:      # 일부 청크는 choices가 비어 있다
        continue
    piece = chunk.choices[0].delta.content
    if piece:
        print(piece, end="", flush=True)   # flush 없으면 버퍼링되어 효과 없음
```

## 5. 관통하는 교훈 — 반복해서 만난 문제

### 5-1. 🔁 "프로세스는 시작 시점의 환경을 복사한다" — 6회 발생

이번 주차에서 **가장 많이 시간을 잡아먹은 원인**이며, 서로 달라 보이는 증상이 모두 같은 원리였다.

| # | 증상 | 상황 |
|---|---|---|
| 1 | 설치 후에도 `az` 인식 실패 | 설치 전 열린 셸이 옛 PATH 보유 |
| 2 | VS Code 새 탭에서도 실패 | 새 탭은 VS Code 프로세스 환경을 상속 |
| 3 | Ollama 업그레이드 후 CUDA 오류 | 실행 중이던 프로세스 상태 불일치 |
| 4 | 새 MCP 서버 도구 미로드 | 실행 중인 세션에 반영되지 않음 |
| 5 | `OLLAMA_KEEP_ALIVE` 미적용 | `SetEnvironmentVariable`은 레지스트리만 갱신, 현재 `$env:`는 그대로 |
| 6 | macOS GUI 앱이 nvm Node 미탐색 | GUI 앱은 `~/.zshrc`를 읽지 않음 |

> **실무 규칙: 무언가를 설치·변경한 뒤 "안 된다"면 먼저 재시작을 의심한다.** 그리고 "터미널 재시작"으로 부족한 경우가 많다 — **호스트 앱 자체**를 재시작해야 한다.

### 5-2. 오류 메시지는 결과이지 원인이 아니다

| 메시지 | 겉보기 | 실제 |
|---|---|---|
| `Invalid selection` | 로그인 실패 | **로그인 성공** (구독 1개라 기본값 자동 선택) |
| `No subscriptions found` | 구독 없음 | MFA 중단의 부산물 (구독은 존재) |
| `invalid character 'ï'` | JSON 문법 오류 | UTF-8 **BOM**을 Go 파서가 거부 |
| `ollama ps` 비어 있음 | 메모리 여유 있음 | **좀비 `llama-server`가 2.82 GB 점유 중** |

> **메시지를 읽고 바로 재시도하기보다 상태를 직접 조회하는 편이 빠르다.**

### 5-3. 정상 경로 테스트는 절반만 검증한다

실패 경로를 강제로 재현했기에 잡힌 버그 — `with_retry()`의 맨몸 `raise`가 `except` 블록 밖에 있어 `RuntimeError: No active exception to reraise`가 발생했다.

```python
# ❌ except 블록이 끝나면 파이썬은 예외 변수를 자동 삭제한다
except RETRYABLE as e:
    kind = type(e).__name__
if attempt == MAX_ATTEMPTS:
    raise                      # 활성 예외 없음

# ✅ 예외를 보관해 명시적으로 던진다
except RETRYABLE as e:
    last_exc, kind = e, type(e).__name__
if attempt == MAX_ATTEMPTS:
    raise last_exc
```

또한 **실패 주입은 대상이 복구할 수 없는 지점에 걸어야 한다.** Ollama 프로세스를 죽여 실패를 만들려 했으나 앱이 자동 재기동해 무력화됐고, 존재하지 않는 포트를 가리켜서야 검증됐다.

### 5-4. 측정 조건이 결과를 지배한다

같은 `gemma3:12b`가 조건에 따라 **50배 차이**를 보였다.

| 측정 조건 | 지연 |
|---|---|
| 단독 웜 (메모리 상주) | 7.7초 |
| 3종 번갈아 호출 (스래싱) | 50.1초 |
| 갓 다운로드 후 콜드 | 394초 |

> 벤치마크 숫자를 인용할 때는 **측정 조건을 반드시 함께 적어야 한다.**

| 3 | AI 기반 **데이터** | 분석·설계·개발·검증, 데이터 파이프라인, 품질·거버넌스 |

### 6-2. 1주차 → 2주차 연결

| 1주차에서 만든 것 | 2주차에서 확장되는 방향 |
|---|---|
| `app.py`의 재시도·스트리밍 | **품질/평가·검증** — 수용기준(AC)과 테스트를 1:1 매핑 |
| `router.py`의 모델 라우팅 | **AI 통합 패턴** — 앱 아키텍처 수준의 모델 선택 전략 |
| Azure CLI로 서비스 조회 | **IaC** — 조회에서 끝내지 않고 선언적으로 **프로비저닝** |
| `.env` 설정 분리 | **환경별 구성 관리** — dev/staging/prod 분리, 시크릿 관리 |
| MCP 도구 연결 | **Claude Code 실습** — 2주차는 Claude Code로 인프라·검증을 직접 수행 |
| 수동 실행·검증 | **MLOps 수명주기** — 재현 가능한 자동화로 전환 |

### 6-3. 2주차 전에 정리하면 좋을 것

- [ ] **Azure 리소스 실제 생성** — 1-2에서 조회만 했다. 2주차 IaC 실습 전에 리소스 그룹과 AI 서비스를 한 번 만들어보면 이해가 빠르다.
- [ ] **`.env.example` 추가** — GitHub에 올릴 때 `.env`는 제외되므로, 키 없는 템플릿을 두면 다른 기기에서 재현이 쉽다.
- [ ] **EARS 5패턴 예습** — 2주차의 요구사항 작성 기법. 1주차에서 만든 `app.py`의 재시도 동작을 EARS로 기술해보면 연결이 자연스럽다.
