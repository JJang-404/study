## 3단계 · 임베딩 / 인덱싱

| 항목 | 값 |
|------|-----|
| 임베딩 모델 | `paraphrase-multilingual-MiniLM-L12-v2` |
| 지원 언어 | 50개 이상 (한국어 포함) |
| 임베딩 차원 | 384차원 |
| 벡터 수 | 14개 |
| 임베딩 소요 시간 | 0.14s |
| L2 정규화 | 저장 시 적용 — 평균 norm = **1.000000** |
| 왕복 검증 | 저장 후 재로드 → norm 재확인 (assert abs(norm - 1.0) < 1e-4) |
| 저장 파일 | `index.npz` (단일 파일) |
| 파일 크기 | 36,307 bytes |
| 담당 모듈 | `indexer.py → build_index()` |

### 벡터 L2 정규화 이유

L2 정규화(단위 벡터화)를 저장 시점에 적용하면:
- **dot product = cosine similarity** 가 성립 (검색 시 나눗셈 연산 생략 가능)
- 모든 벡터의 크기(magnitude)가 1이 되어 방향(의미)만 비교
- `np.linalg.norm(vectors, axis=1, keepdims=True)` 로 각 행을 정규화

### `index.npz` 구성

`np.savez()` 로 저장된 단일 파일에 아래 배열들이 key-value 형태로 묶입니다.

| 키 | dtype | shape | 설명 |
|----|-------|-------|------|
| `vectors` | float32 | (14, 384) | L2 정규화된 임베딩 벡터 |
| `ids` | int32 | (14,) | 청크 순번 |
| `texts` | object | (14,) | 청크 본문 텍스트 |
| `starts` | int32 | (14,) | 원본 텍스트 시작 오프셋 |
| `ends` | int32 | (14,) | 원본 텍스트 종료 오프셋 |

로드 예시:
```python
npz = np.load("index.npz", allow_pickle=True)
vectors = npz["vectors"]   # (14, 384) float32
ids     = npz["ids"]       # [0, 1, 2, ..., 13]
texts   = npz["texts"]     # 청크 텍스트 배열
```

## 4단계 · 검색 (retrieval)

| 항목 | 값 |
|------|-----|
| 검색 모드 | `semantic` 또는 `hybrid` (기본값: hybrid) |
| 시맨틱 검색 | 질의 임베딩 → dot product (= cosine similarity, L2 정규화 덕분) |
| 키워드 검색 | BM25 (rank_bm25) + 한국어 문자 2-gram 토크나이저 |
| 융합 방식 | RRF (Reciprocal Rank Fusion, k=60) |
| top-k | 3 (기본값) |
| 검색 소요 시간 | ~0.07s |
| 담당 모듈 | `search.py → search()` |

### 검색 모드 비교

| 모드 | 원리 | 장점 | 단점 |
|------|------|------|------|
| semantic | 임베딩 벡터 간 유사도 | 의미 기반 검색, 동의어·패러프레이즈에 강함 | 철자 완전 일치 키워드에 약할 수 있음 |
| hybrid | semantic + BM25 → RRF 융합 | 의미 + 키워드 양쪽 커버 | 토크나이저 품질에 의존 |

### 한국어 BM25 토크나이저

기본 공백 분리(`.split()`)만 사용하면 `재시도해도` ≠ `재시도` 처럼 어미 결합으로 매칭 실패.
→ 한글 문자 2-gram을 추가 토큰으로 생성해 부분 매칭 보완:

```python
stripped = text.replace(" ", "")
bigrams = [stripped[i:i+2] for i in range(len(stripped) - 1)]
tokens = text.split() + bigrams
```
